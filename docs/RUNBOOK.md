## 4. iLO access pattern (repeatable)

```bash
# login (from ~/.env PASSWORD or Doppler PASSWORD — by reference)
set -a; source ~/.env; set +a
curl -k -s -m 30 -X POST -H "Content-Type: application/json" \
  -d "{\"UserName\":\"ops\",\"Password\":\"$PASSWORD\"}" \
  https://192.168.1.216/redfish/v1/SessionService/Sessions/ \
  -D /tmp/ilo_headers.txt -o /dev/null
TOKEN=$(grep -i x-auth-token /tmp/ilo_headers.txt | awk '{print $2}' | tr -d '\r')
printf '%s' "$TOKEN" > /tmp/ilo_token
```

Key Redfish endpoints:
- `GET /redfish/v1/Systems/1/` — power state
- `POST .../Systems/1/Actions/ComputerSystem.Reset/` — `{"ResetType":"On"|"ForceOff"|"ForceRestart"}`
- `GET /redfish/v1/Chassis/1/Power/` — draw watts
- `GET /redfish/v1/Chassis/1/Thermal/` — CPU temps
- `GET /redfish/v1/Managers/1/LogServices/IEL/Entries/` — event log

**iLO gotchas (learned the hard way):**
1. **Login throttling**: repeated logins trigger LoginDelay / session pool
   exhaustion ("no more free sessions"). Clear sessions:
   `DELETE /redfish/v1/SessionService/Sessions/{id}` for each, keeping yours.
   Space logins out. The pool is small.
2. **Virtual media mounts DROP on iLO power cycles.** Always re-mount before
   boot: Proxmox ISO + cidata answer file. Script pattern in
   `/tmp/opencode/ilo-premount.sh` (Playwright web UI) — recreate if tmp
   cleared. Both slots: floppy=cidata, disc=proxmox ISO.
3. **"No video" on console** = board powered but POST not initializing video.
   A force-cycle (ForceOff → wait 20s → On) reliably gets video out.
   Draw ramps 0W → ~110W → ~230W → ~150W when POST actually runs.
4. **ISO server (Range-aware)** must run for the iLO to fetch media:
   `node scripts/iso-server.mjs bootstrap 8010`. Firewall must allow
   `8010/tcp` (`sudo ufw allow 8010/tcp`) — the firewall was silently
   blocking the iLO's fetch for a long time. iLO fetches via RANGE requests.
5. **Boot order**: RBSU set IPL to CD top (LO did this) so the server boots
   the installer ISO. To get INTO RBSU: iLO boot_order page has a
   "Boot to System RBSU" button (`#rbsu_button`) — the reliable way.
6. **HTML5 console** for seeing/typing into the screen: login via Playwright,
   app frame `window.startHtml5Irc()`, then
   `window.renderer.keyboard.send_vkey('F9', true/false)` sends keys.
   Capture the `#videoContainer` region via
   `page.screenshot({clip: rect})` → OCR with tesseract.

## 6. POST-INSTALL checklist (the real work)

1. **Detect the 1TB drive**: `lsblk`, `lsscsi`, `smartctl -i /dev/sdX`.
   If P420i array unconfigured: F8 (Option ROM) or SSA to build the array,
   OR the 1TB may be a separate SATA disk. Configure it as the VM-data pool.
2. **Run `bootstrap/post-install.sh`** on the host (as root):
   - creates `vmbr1` NAT bridge (10.10.10.0/24) for test VMs
   - creates encrypted `rpool/vmhub` ZFS dataset (aes-256-gcm) with keyfile
     at `/etc/zfs/keys/vmhub.key`, auto-loaded at boot (no boot password)
   - creates scoped `vmhub@pve` API token — token prints ONCE, that's LO's
     to capture into Doppler as `PVE_TOKEN` + `PVE_HOST`
   - the 1TB drive becomes the storage where VMs actually live
3. **Deploy vmhub via Doppler**:
   `doppler run --project proxmox --config prd -- ./deploy/install.sh`
   (renders PVE_HOST/PVE_TOKEN into /etc/vmhub/*.env by reference)
4. **Verify the full loop** (from the plan's Definition of Done):
   `vm_list_templates → vm_lease_create → poll ready → vm_screenshot/click/
   type → vm_put_file → vm_clone_repo → vm_get_file → vm_lease_release`
   across hyprland + real VM adapters.
5. **Beep**: confirm POST shows 128GB (reseat result); if beep persists, RBSU
   POST Error Beep = Disabled.
6. LO handoff: brief them on PVE_HOST, that PVE_TOKEN is ready to capture,
   and the 1TB-drive finding.

## 7. vmhub architecture (30-second version)

- `src/mcp/` — 22 vm_* tools, the only interface agents see
- `src/lite/` — control plane: 8 REST endpoints, SQLite, Proxmox client (mock
  until real)
- `src/reaper/` — independent lease reaper, identity-verified teardown
  (tag `vmhub-<prefix>-<uuid>`, never VMID), drains in-flight transfers,
  24h cap, 15% disk-full refusal. Runs via systemd timer OnBootSec=1min.
- `src/shared/types.ts` — the Capability contract (single source of truth)
- Adapters: hyprland (spawn existing binary), x11/windows/macos/android
  (mock), ios (stub)
- Reboot survival: `deploy/systemd/` units + `deploy/install.sh`
- Docs: `docs/architecture.md`, `docs/storage-fde.md`,
  `docs/reboot-survival.md`, `docs/probe.md`, `docs/gates.md`,
  `docs/setup.md`, `skills/vm-operator/`
